# 任务作业：多语言、Cron、执行历史与回滚

## 功能范围

任务中心的“任务模板”和“任务作业”现支持以下执行类型：

| 类型值 | 类型 | 远端执行方式 |
| --- | --- | --- |
| 1 | Shell | `bash script.sh` |
| 2 | Python | `python3 -u script.py`（关闭标准输出缓冲） |
| 3 | Ansible Playbook | `ansible-playbook playbook.yml` |
| 4 | JavaScript | `node script.js` |
| 5 | PowerShell | `pwsh -NoProfile -File script.ps1` |
| 6 | Go | `go run script.go` |
| 7 | Ruby | `ruby script.rb` |
| 8 | PHP | `php script.php` |
| 9 | Perl | `perl script.pl` |
| 10 | 直接命令 | `bash -lc '<command>'` |

目标服务器必须安装对应运行时，并提供 `setsid`（通常由 util-linux 提供）以支持安全的进程组暂停和停止。脚本内容通过 Base64 写入唯一临时文件，避免脚本正文参与远端 Shell 拼接；执行结束后临时脚本、PID、退出码和远端日志文件会被清理。

## 任务模式

- 手动任务：仅在用户点击“立即执行”时运行。
- 定时任务：使用标准 5 位 Cron（分、时、日、月、周）；定时开关控制自动调度。
- 定时任务也可点击“立即执行”，该操作不会改变原有定时开关状态。
- 执行内容可来自一个或多个任务模板，也可直接在任务作业中填写命令或脚本。

## 任务分组与列表

任务作业支持独立分组：在“分组管理”中新增、重命名或删除分组，在任务创建/编辑表单中选择所属分组。复制任务时保留分组，按分组筛选时新建任务默认使用当前分组。旧任务默认“未分组”。

列表可组合使用名称、状态和分组筛选，筛选发生在服务端并返回对应分页总数。删除分组只将关联任务移至“未分组”，不会删除任务、工作项或历史，也不会改变运行状态。

任务作业操作列为单行图标：执行/暂停/恢复、日志/历史、更多操作；停止、带参数执行、复制、编辑和删除位于“更多操作”。列表和历史分页居中。Ansible 操作列同样为单行，运行中显示停止按钮，其他状态显示启动按钮。

分组接口使用现有任务模块读写权限：`GET/POST /api/v1/task/groups`、`PUT/DELETE /api/v1/task/groups/:group_id`。任务创建和更新支持可空的 `group_id`；列表查询省略 `group_id` 表示全部，`group_id=0` 表示未分组，正整数表示对应分组。

## 执行历史

每次手动或定时触发都会创建一条 `task_execution_history`，并为每个“主机 × 模板”创建 `task_execution_log`。记录包含：

- 触发方式和执行人；
- 当次任务名称、主机、Cron 和备注；
- 当次实际执行的模板/命令快照；
- 每个主机的状态、开始/结束时间、耗时和完整日志。

`max_history_keep` 控制每个任务最大保留记录数，范围为 1–200，默认 20。一次执行汇总完成后会自动删除超限的最旧历史、子日志和对应本地日志文件。

## 参数复用

模板和任务都支持 `parameters`（字符串键值对象）。界面可逐项编辑，也可批量导入 JSON / YAML；嵌套值会转换成 JSON 字符串。优先级从低到高为：

1. 当前模板的默认参数；
2. 任务作业保存的覆盖参数；
3. “更多操作 → 带参数执行”填写的本次临时参数。

空字符串会覆盖默认值，删除覆盖项则恢复继承。多模板任务分别继承各自的默认参数，共享任务级和本次执行的覆盖值。修改模板默认参数只影响后续执行；临时参数不会修改模板或任务。任务可通过“更多操作 → 复制任务”复用配置，再调整名称、主机或参数。

参数作为环境变量传入，不进行脚本文本替换。例如模板默认参数为 `{"APP_NAME":"orders","VERSION":"v1"}`，任务只需填写 `{"VERSION":"v2"}`：

```bash
printf '部署 %s，版本 %s\n' "$APP_NAME" "$VERSION"
```

Python 使用 `os.environ["APP_NAME"]`，Node.js 使用 `process.env.APP_NAME`，Ansible Playbook 使用 `lookup('env', 'APP_NAME')`。参数名使用字母、数字、下划线，且不能以数字开头。

`POST /api/v1/task/:id/run` 可不带请求体，也可传入 `{"parameters":{"VERSION":"v3"}}`。执行历史保存模板默认参数、任务与临时参数合并后的值，以及逐工作项最终生效的参数。参数会出现在历史详情中，请使用现有凭据管理功能保存密码。

## 实时日志

任务开始前会建立本地日志文件并登记路径，远端输出通过持续的 SSH 通道写入该文件。启动任务后自动打开日志窗口，也可从运行中的任务行进入“实时日志”。窗口每秒读取执行详情，支持自动滚动、手动刷新、断线重试；关闭窗口或执行结束会停止自动刷新。

运行中的日志窗口最多返回最近 2 MiB，完成后在历史中保留完整日志。脚本或程序自行缓冲的输出仍需程序主动刷新；Python 执行器默认使用 `-u`。远端日志跟随只读取新增字节，并在结束时读取最后一段输出。日志连接失败不会自动重新执行命令。

## 暂停、恢复与停止

- “暂停执行”向该次执行的远端进程组发送 `SIGSTOP`，状态和执行历史显示为“已暂停”。
- “恢复执行”发送 `SIGCONT`，队列中尚未启动的工作项也会遵守暂停状态。
- “停止执行”先发送 `SIGTERM`，进程未退出时再发送 `SIGKILL`；历史状态记录为“已停止”，已产生的日志继续保留。
- 定时调度开关与当前执行状态相互独立：停止某一次定时执行不会关闭后续 Cron 调度；暂停 Cron 调度也不会隐式杀死已经开始的命令。

## 回滚语义

历史列表中的“回滚”恢复该次执行时的任务配置和模板内容，包括命令、语言、模板默认参数、当次任务有效参数、主机、Cron 与备注。回滚只恢复配置，不会自动执行。

运行中的普通任务不能回滚；已启用自动调度的定时任务需先暂停，以避免调度器继续使用旧配置。若历史中的模板已删除，回滚会重建模板并更新任务关联。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/task/:id/run` | 手动立即触发一次 |
| POST | `/api/v1/task/:id/schedule` | 启用 Cron 调度 |
| POST | `/api/v1/task/:id/execution/pause` | 暂停当前执行 |
| POST | `/api/v1/task/:id/execution/resume` | 恢复当前执行 |
| POST | `/api/v1/task/:id/execution/stop` | 停止当前执行 |
| GET | `/api/v1/task/:id/history` | 分页查询执行历史 |
| GET | `/api/v1/task/:id/history/:history_id` | 查询命令快照和逐主机日志 |
| POST | `/api/v1/task/:id/history/:history_id/rollback` | 恢复该次执行配置 |

## Ansible 任务记录

Ansible 任务列表的任务名称已作为可点击入口，路由到隐藏菜单页 `/task/ansible/history?id=<taskID>&name=<taskName>`，复用现有 `AnsibleTaskHistory.vue` 页面。

Ansible 编辑接口支持修改和清空任务描述、额外变量、CLI 参数、全局变量和 Cron。未传入的字段保持原值；相同的 Playbook 列表不会重新校验或重建子任务。修改名称后继续使用原工作目录，真正修改 Playbook 路径时才校验文件，并事务性更新子任务。手动配置的变量和主机清单在每次执行前重新生成，避免继续使用创建时的旧文件。

## 更新部署

重新构建并部署 API 与 Web。现有启动迁移会为 `task_template`、`task_job`、`task_execution_history`、`task_execution_log` 增加 `parameters` 字段；旧记录的空参数保持兼容。迁移同时新增 `task_job_group` 表和 `task_job.group_id` 字段。使用现有 Docker Compose 部署时，重建对应的 API / Web 服务即可，不需要增加环境变量或挂载。

若任务作业页面请求 `/api/v1/task/groups` 返回 404，而任务列表接口存在，应检查 API 监听端口实际由哪个进程提供服务，例如 `ss -ltnp 'sport = :8000'`。旧进程可能仍占用端口，导致新 API 没有接管请求。确认没有正在执行的作业后停止旧进程，再启动当前版本。API 现已在数据库迁移和后台调度启动前绑定端口，端口冲突时会明确报错并退出，避免未监听的实例继续执行后台任务。
