# 数据库管理建设方案

更新日期：2026-11-04。本文保存数据库平台的架构、功能边界和交付计划；实际测试结果另见 [联调与验收记录](2026-11-01-database-platform.md)。本文中的目标不代表已经完成生产验收。

## 1. 产品结构与交互

数据库管理独立于资产管理。采用“数据源、实例、集群、部署任务”四层关系：数据源描述客户端连接，实例描述某主机上的数据库进程，集群描述复制/分片/高可用，部署任务通过 Ansible 创建和维护服务。

当前子菜单及职责：

| 顺序 | 子菜单     | 页面内容与操作入口                                                  |
| ---- | ---------- | ------------------------------------------------------------------- |
| 1    | 数据源管理 | 连接、业务分组、直连/集群连接、工作台和终端；不展示部署与高可用面板 |
| 2    | 集群管理   | 集群列表、概览、拓扑、节点、复制状态；每行提供详情与操作菜单        |
| 3    | 存储管理   | 容量、实例/文件系统、持久化与日志；本模块执行采集及受保护维护       |
| 4    | 备份恢复   | 策略、备份集、仓库、归档、隔离恢复与恢复验证                        |

操作审计位于 **基础管理 → 数据日志 → 数据库操作审计**，涵盖任务、事件、步骤、日志与中断核验。数据库四个子菜单统一图标与顺序。

本次产品调整已取消独立“监控诊断”菜单和集群详情中的诊断标签。五维健康采集、过期状态及监控中心告警集成保留。

列表统一按业务分组（包含后代分组）、引擎、环境、状态和名称筛选。数据库标识复用运维工具中的 MySQL、Redis、PostgreSQL SVG 图标。集群行操作导航到其他模块时携带可清除的集群筛选，存储、备份保留独立页面，审计迁入基础管理的数据日志；参数配置收进集群详情标签，通过行操作中的“参数配置详情”进入。

所有集群运维操作不要求填写操作原因或手工输入集群名称。无参数动作自动预检，有参数动作填写必要目标后预检；通过后点击“确认执行”。确认弹窗展示目标集群、动作及阻断项。取消不提交任务。服务端仍校验权限、计划版本、幂等键及集群互斥锁。

MySQL 工作台继续提供库表浏览、表格编辑、导入导出、基础配置和终端；命令提示只在输入行显示虚影，Tab 补全，不设右侧提示面板。

## 2. 实施边界与接管

- 沿用 CMDB 主机 + Ansible + systemd；首轮适配既有版本，不同时升级数据库大版本。
- 支持单机、MySQL GTID 主从、Redis Sentinel、Redis Cluster、PostgreSQL Patroni。
- 新建、只读发现和接管均支持。接管默认观察模式，不自动改密码、复制关系或选主策略。
- 运维托管允许按授权执行维护；高可用托管需要隔离、入口和故障演练验收。发现现有控制器时，不部署第二套选主机制。
- Kubernetes Operator、跨地域多活、MySQL MGR/Galera、PostgreSQL 多主及自动磁盘/LVM 扩容不纳入本轮。

新建流程：选择业务分组和拓扑 → CMDB 主机、资源、端口和目录 → 凭据、入口与保护策略 → 预检和确认 → Ansible → 验证复制/入口 → 登记实例及数据源。

预检覆盖权限、主机身份、端口、目录归属、磁盘/内存、时间同步、连通性、版本、现有控制器和故障域。每个实例有独立成员 ID、端口、服务名和数据目录；主机 ID 不能代替实例身份。

## 3. 三引擎集群与高可用

### MySQL

架构：主库 + 两个副本，三节点 Orchestrator Raft，双 HAProxy 写/只读入口；生产稳定入口使用显式配置的 VIP 或既有负载均衡。

- 查看 GTID、复制线程、错误、延迟和只读状态；支持副本扩展、重建、维护、计划切换、恢复与旧主重加入。
- 计划切换收敛写入、追平复制、校验候选、变更角色并验证业务入口。
- 恢复前钩子调用独立隔离执行器；独立管理通道确认旧主停止或写入路径受控，失败返回非零阻止提升。不能把单侧端口不可达视为已隔离。
- 旧主核验 GTID 分叉后才重加入，有分叉则保留原目录并重建。业务写入口只放行已确认可写主库，只读入口排除过度延迟副本。
- 半同步可配置并显示实际退化状态；Raft 多数派不表示 MySQL 数据已在多数节点持久化。Orchestrator 固定发行版本和适配层，不跟随已归档仓库主分支。

### PostgreSQL

架构：三个 PostgreSQL/Patroni、三节点 etcd、双 HAProxy。实验环境可同机，生产分别评估数据与控制资源。

- 展示 WAL/LSN、timeline、复制槽、同步副本与延迟。计划切换、副本扩展/重建、维护和滚动重启通过 Patroni 执行。
- 新建默认 `synchronous_mode`、`synchronous_mode_strict` 和一个同步副本；不足时暂停写入，不静默降级为异步。
- 代理写入口检查 Patroni `/primary`，读入口检查 `/replica` 与延迟限制。
- 旧主满足前置条件才执行 pg_rewind，否则从有效基线重建。生产高可用验收须验证 watchdog/隔离；缺少证据不能标为已验收。
- 控制组件安装版本、依赖哈希与兼容测试单独维护；不能把管理器健康页面当成数据一致性证明。

### Redis Sentinel 与 Cluster

| 项目     | Sentinel                      | Cluster                          |
| -------- | ----------------------------- | -------------------------------- |
| 默认节点 | 一主两从、三个 Sentinel       | 三主六从，每个分片两个副本       |
| 入口     | Sentinel 列表 + masterName    | Cluster 种子地址                 |
| 运维对象 | 复制组、偏移、quorum 和多数派 | 分片、节点、16384 槽位、迁移状态 |
| 扩缩容   | 增副本、重建、原生切换        | 建立分片/副本、迁槽、迁空后退役  |

选主使用原生机制，AutoOps 不另写选主算法。Sentinel 的故障判断 quorum 与授权切换所需多数派分别表达。Cluster 迁槽按批记录，中断后读取实际槽位/键状态续行，禁止盲目从头重放；仍有槽位的主节点不能直接停止移除。

默认 noeviction，要求至少一个有效副本并限制延迟；三主三从可接管，但保护策略可能让故障分片暂停写入。每个复制组的节点跨故障域分布；原生切换后可能失衡，需要采集检查及显式调整。

Redis 异步复制仍有已确认写入丢失窗口。工作台只允许 Cluster DB 0，处理 MOVED/ASK，按主分片 SCAN 并使用拓扑版本复合游标；跨槽操作遵守原生限制，不使用全量 KEYS 或长期 MONITOR。

## 4. 存储、备份恢复与参数

### 存储

区分逻辑数据量、所有副本占用、主机文件系统容量，文件系统按真实主机/设备去重。容量默认 80% 提醒、90% 严重，支持业务分组继承覆盖；采样不足不预测剩余天数。

MySQL 查看库表/索引、binlog、redo/undo 和临时空间；binlog 清理同时检查副本依赖、归档和恢复窗口。PostgreSQL 查看表空间、WAL、归档与复制槽，不提供直接删除 WAL 文件的操作。Redis 查看内存/RSS/碎片率和 RDB/AOF；持久化动作检查磁盘、内存、复制健康和重型任务互斥。只输出磁盘扩容评估，不自动分区或修改 LVM。

### 备份恢复

| 引擎       | 备份链                                        | 恢复能力              |
| ---------- | --------------------------------------------- | --------------------- |
| MySQL      | mysqldump、版本匹配的 XtraBackup、binlog 归档 | 全量/增量、时间点恢复 |
| PostgreSQL | pgBackRest 全量/差异/增量、WAL                | 时间点恢复、副本基线  |
| Redis      | RDB、AOF 检查；Cluster 按分片                 | 实例及逐分片恢复      |

仓库支持受管本地目录和 S3 兼容协议。生产副本应独立于数据库节点；本地暂存成功不表示远端成功。备份集保存版本、实例身份、复制坐标/timeline、校验值、文件清单、依赖链、可恢复范围和验证结果。

默认恢复到新实例或隔离目录：选择备份/目标时间 → 检查依赖链 → 恢复 → 隔离启动 → 校验数据 → 报告；投入使用需独立切换任务。按 2026-11-02 产品调整，手动清理不受保留时间、历史父链或后继验证副本限制；只删除指定自包含备份包及其仓库副本。迁槽期间不做常规分片备份，逐分片备份不宣称跨分片统一事务快照。

MySQL 工具按数据库版本匹配，当前固定配置的具体兼容范围以源码和联调文档为准。归档可恢复范围只按实际取得的完整日志链计算，不能把定时导出已关闭段宣称为连续流式归档。

### 参数

展示期望/实际、差异、版本、动态/reload/重启属性和待重启项。配置文件由 Ansible 模板管理；高可用参数通过原生管理器，不绕过 Patroni/Sentinel。按副本逐台应用并核验后再继续，主节点单独切换或维护。工作台运行时参数纳入同一记录与审计，单实例变更不能影响其他实例。

## 5. 后端、接口与可靠性

新增领域对象包括集群、成员、访问入口、存储快照、备份策略/备份集/仓库、任务/步骤、配置版本、事件。适配层统一发现、健康、拓扑、能力、预检、执行与结果核验。

主要 API 前缀 `/api/v1/database`：

| 资源                                          | 职责                                                 |
| --------------------------------------------- | ---------------------------------------------------- |
| clusters、discovery                           | 列表、新建、只读发现和接管                           |
| clusters/:id/topology、members、capabilities  | 真实拓扑、实例、授权后的能力                         |
| clusters/:id/operation-plans、operations      | 预检计划与提交                                       |
| operations/:id、events                        | 步骤、状态、日志、原生事件                           |
| storage、storage-thresholds、repositories     | 容量、阈值和仓库                                     |
| backup-policies、backups                      | 策略、备份链；restore/verify-backup 作为统一任务提交 |
| clusters/:id/configurations、config-revisions | 实际/期望参数与配置历史                              |

执行请求使用 `planId`、`idempotencyKey`、`confirmed: true`。保留旧 `confirmName` 请求兼容；新界面不要求输入。计划绑定用户、拓扑版本和有效期，过期必须重做预检。

独立 Worker 运行持久化任务：排队 → 预检 → 执行 → 核验 → 成功/失败/结果待核验。集群变更互斥，普通 SQL 查询和业务 DML 不进入锁。Worker 退出后先核对远端状态，租约和世代号不能证明旧远端命令已停止；切换、恢复、迁槽不能承诺通用回滚。

AutoOps API 不在线时原生高可用和独立隔离仍需工作。元数据库、Worker 基础设施与故障测试集群分离。健康展示数据库、复制、控制、入口、备份五个维度；采集过期显示未知及最后采集时间。

## 6. 权限、迁移与部署

保留 `database:read/write/execute` 平台权限；集群资产级动作为 `db_cluster_view/manage/switch/backup/restore/config/audit`。查询权不升级为维护权；加入主机需部署权，API Key 同样检查动作和资产范围，队列执行/定时调度再次验证授权。

保留已有数据源 ID、账号、业务分组和授权；旧部署按主机+端口映射成员，历史备份继续查询。接管不覆盖外部控制策略。`/cmdb/databases/*` 和旧部署接口保留兼容桥接，避免维护两套同一集群状态。

前后端菜单同步更新，已存在诊断菜单迁移为禁用，保留历史角色关联。Docker/Compose 与 Kubernetes 更新 AutoOps API/Worker 的运行配置；受管数据库仍使用主机 Ansible，不通过 Kubernetes 部署。

| ---- | ------------------------------------------------ | -------------------------------- |

| P2   | Worker、计划、MySQL 隔离/Orchestrator/双代理     | 主节点和代理故障后的业务读写     |

每阶段交付前后端、自动化、测试和文档；菜单或模拟拓扑不能作为完成依据。产品界面采用本文第一节五模块划分，不恢复已取消的诊断模块。

## 8. 验收环境与矩阵

既有授权隔离环境为 CMDB `.51/.52/.53`，每次真实执行前重新核对资源和服务归属。Sentinel 每台一个数据节点和一个控制节点；Cluster 每台三个实例并跨主机配置同分片副本；PostgreSQL/etcd 与 MySQL 使用独立服务、端口和目录。宿主机重启、断电与硬件 watchdog 测试使用可销毁环境，不影响现有其他服务。

必测项目：

- 兼容与界面：新建、观察接管、管理级别、旧 API/工作台、父子分组、五菜单、行操作、取消/确认、图标、明暗主题和过期状态。
- 权限与任务：跨组、仅 SQL 用户、受限 API Key、未授权主机、重复提交、并发、过期计划、API/Worker 重启、远端完成但请求超时。
- 高可用：主/副本进程、旧主返回、控制组件 Leader/多数派、网络分区、代理故障、客户端重连；API 离线时原生恢复。
- Redis：槽位缺失、迁移中断续行、扩缩容、MOVED/ASK、DB 0/跨槽限制和故障域分布。
- 存储与恢复：限定测试卷写满、归档断点/积压、仓库故障、保护依赖日志、实际恢复文件和业务数据、PITR 边界。

正常网络、资源充足的单节点进程故障，初始 RTO 目标 60 秒，每拓扑连续三轮。从客户端最后一次成功到恢复连续成功计时；记录确认写入与结果未知写入并核对 RPO。隔离失败或网络分区触发保护性停写时，按正确阻断验收，不为 RTO 强制提升。异步复制不能承诺零丢失。

当前已为隔离联调部署 MySQL 与 PostgreSQL VIP（详见 [VIP 教程](database-vip-guide.md)）；仍缺少 S3 与可销毁 watchdog 环境。高可用验收与恢复验证必须有对应证据，历史失败不能覆盖或补写成成功。

## 12. 列表、采集与 VIP 增量交付

- 存储、备份、数据源和集群列表统一 64px 行高、26px 数据库图标；分页包含总数、每页数量、页码和跳页。所有列表先授权和筛选再分页，存储先选择最新快照并去重，分类切换回到第一页。
- API 与 Worker 共享只读 Collector，通过集群租约协调，每 15 秒扫描一次；单个集群故障不会串行阻塞全部集群。90 秒过期边界保持，显示实际最后采集时间，不把未知改成健康。元数据库连接使用一致时区。
- 拓扑增加组件图标、复制流动动画和 VIP 卡片，展示绑定主机、实际链路、复制线程、采样位点差及采集时间。MySQL 用 GTID 包含关系、PostgreSQL 用 WAL 回放位点、Redis 用同复制 ID 的 offset 核验追平；动画只表示本次采样证据，不能承诺全量一致性或零数据损失。
- 审计新增 `GET/PUT /api/v1/database/audit-policy` 与 `DELETE /api/v1/database/audit/:kind/:id`。默认保留 90 天（0 为永久），管理员可以删除；未结束、结果待核验、持锁任务继续保留。删除步骤日志和事件内容，不破坏幂等回执与备份引用。
- VIP 配置与漂移验证复用计划、预检、确认、持久化任务、主机权限与远端执行世代。每个集群使用独立 Keepalived 服务；先设置 60 秒恢复定时器再停止原承载服务，验证唯一绑定、新承载、连续 SQL 主库连接并恢复原服务。该结果与数据库故障切换、写入 RPO、完整 HA 验收分别记录。

实施细节及真实地址见 [VIP 配置、演练与排查教程](database-vip-guide.md)。

## 13. HTTP 访问下的操作提交修复（2026-11-01）

预检接口返回与计划绑定的 `idempotencyKey`（`db-plan-<planId>`），前端直接使用；旧后端没有该字段时，按计划 ID 推导相同格式。生成过程不调用浏览器 Crypto API，因此局域网 HTTP 地址同样可用。

同一计划提交超时或响应丢失后重试，继续复用原键；重新预检产生新计划和新键。只有计划与有效键同时就绪才展示可确认状态，预检失败或弹窗关闭会清除旧状态，迟到响应不能覆盖新弹窗。后端仍执行 8–80 字节校验、确认校验、请求归属、幂等冲突与集群互斥，不通过放宽校验消除报错。

回归命令：`node web/scripts/database-operation-check.cjs`；后端运行 `go -C api test ./api/database/... ./pkg/db/... ./router/database/...`。

## 14. 操作确认与切换后状态核验（2026-11-01）

所有通过统一运维任务提交的操作，在预检页点击“确认执行”后再弹出最终确认框，展示集群、动作和目标节点。无需填写原因；取消、关闭以及过期弹窗的迟到确认均不提交请求。同计划响应丢失后重试仍复用原幂等键。

主从切换分开核验“角色与复制”和“业务入口”。原生管理器完成提升后，HAProxy 仍需健康检查周期才能更新路由。入口核验在独立任务步骤中最多等待 30 秒，连续两次只读连接与读写角色检查通过后完成；不重放切换指令。真实超时或角色冲突保留“结果待核验”和互斥锁，报告具体入口。

待核验任务不会阻止只读采集继续更新数据库、复制、控制组件与入口健康；任务结果与集群健康分开展示。排队/执行/核验中的运维任务以及孤立锁仍阻止新采集。恢复执行前继续等待已有采集租约；任务成功只能由原执行链或显式核验任务确认，不能依据一次采集自动解锁。

## 2026-11-02：备份可用性、手动清理与 MinIO

- 备份集只展示完整且已实际恢复验证的备份，移除 ID 列。完整未验证的备份在“恢复演练”入口操作，失败记录在审计排查；不会用隐藏列表代替真实验证。
- 选择操作集群同时筛选列表，筛选后计算分页总数；仓库增加位置搜索（目录 / Endpoint / Bucket）与管理员确认删除。仓库删除仅移除登记，有备份、策略或活动任务引用时须先解除引用。备份策略支持编辑保存位置。
- “清理过期备份”更名“清理备份”。按最新产品约定，手动清理不要求过期、后继备份或父子依赖检查。当前受管备份包自包含恢复材料；仍校验指定包的身份、准确文件/对象路径和散列，集群锁、最终确认及审计继续生效。删除一个备份包不清除其他包，也不直接清理数据库 WAL/binlog。
- 隔离恢复用于数据找回与灾难恢复准备；恢复验证用于演练。当前二者均实际恢复、启动校验后停止实例，保留文件和报告；业务数据核对、正式回灌及入口切换单独安排。详细场景见 [备份恢复使用指南](database-backup-guide.md)。
- CMDB `.53` 部署固定 `RELEASE.2025-04-22T22-12-26Z` 的 MinIO；上游旧版二进制/镜像不可用，使用官方标签源码构建，记录源码与程序 SHA-256，通过受控 Ansible 配置独立 systemd 服务。安装、凭据位置与联调结果见 [MinIO 备份仓库](database-minio-guide.md)。

## 2026-11-03：恢复排队与状态采集修复

发现 MySQL 恢复任务在仅启动 API 的开发环境中一直排队，任务锁同时阻断状态采集。现区分排队、预检和执行阶段：排队继续采集，预检等待既有采集结束，执行中的隔离恢复继续采集源集群，其余拓扑变更维持互斥。未知结果及孤立锁规则不变，不释放变更锁来伪造健康。

开发 debug 模式默认随 API 启动 Worker，支持 auto/embedded/external 配置；Compose/Kubernetes 保持独立 Worker。任务抽屉显示排队秒数和未开始执行的说明，超时等待提示检查执行器。

## 2026-11-04：备份命名、仓库详情与审计归档

数据库管理仅保留数据源管理、集群管理、存储管理、备份恢复四个子菜单，统一图标与顺序。操作审计迁至“基础管理 → 数据日志 → 数据库操作审计”，原 SQL 操作日志保留独立标签，原数据库审计路由兼容跳转。菜单迁移保留历史角色授权并合并至新入口，不放宽 SQL 日志、集群审计或删除权限。

备份增加可选名称，经过预检和持久化任务传递到备份记录，留空自动生成，历史备份仍可查看。仓库增加详情接口及抽屉，展示配置、检查结果、受管备份占用、策略与最近备份；只读取配置中心备注和凭据引用，不返回明文密钥，不把清单统计称为整个桶的实时容量。
