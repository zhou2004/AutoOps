# AI 运维与中英文国际化

## 使用入口

重启 API 服务后，自动迁移创建 `aiops_config`、`aiops_run` 两张表；重新构建前端后，左侧出现 **AI运维**，包含诊断工作台、模型配置、Skills 配置、工作流配置、诊断记录。

1. 管理员在 **模型配置** 新增连接，填写协议、服务地址、实际可用的模型 ID 和可选密钥，保存后执行连接测试。
2. 在 **Skills 配置** 保存诊断指令及依赖模块，例如“检查主机认证、监控覆盖、故障数量，区分事实和假设，给出检查步骤”。Skills 是可复用的诊断指令，不执行上传的代码。
3. 在 **诊断工作台** 选择模型、模块和统计区间，输入问题并开始诊断。选择 Skill 会自动选中其依赖模块；服务端仍会校验模块。结果逐步显示，可停止生成、复制结果、展开业务证据。
4. 多步诊断可在 **工作流配置** 编排：每一步填写名称，引用 Skill 或填写步骤指令；后续步骤接收前一步分析。最多 8 步，全流程共用超时时间。
5. **诊断记录** 只显示当前账号自己的运行记录，保存问题、模型/Skill/工作流 ID、证据、输出和结束状态。

尚未配置模型时显示明确的配置引导，不填充模拟诊断结果。外部工作流可以独立运行，不要求同时配置本地模型。

## 模型协议

| 协议 | 地址示例 | 调用方式 |
| --- | --- | --- |
| OpenAI Compatible | `https://api.openai.com/v1` 或供应商兼容地址 | `POST {baseUrl}/chat/completions`，`stream: true`，SSE |
| Ollama | `http://127.0.0.1:11434` | `POST {baseUrl}/api/chat`，NDJSON |

模型 ID 使用供应商或本地服务中实际存在的名称，不在代码中绑定具体模型版本。OpenAI 兼容服务须支持 Chat Completions 文本流和结束标记；仅提供 Responses 接口的服务不属于该适配器支持范围。连接测试发送一条“只回复 OK”的实际生成请求，因此可能产生模型费用。

API 运行在容器内时，`127.0.0.1` 指向 API 容器。访问宿主机 Ollama 应填写容器可达的宿主机地址，或同一网络中的服务名称，例如 `http://ollama:11434`。不要把本地模型接口无认证地暴露到公网。

实现按 [OpenAI Chat Completions 流事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) 和 [Ollama Chat API](https://docs.ollama.com/api/chat) 处理增量、终止、错误与取消。输出截断、缺少结束标记、供应商错误均记录为失败，保留已输出内容。

## 外部工作流

### Dify

选择 Dify 协议，填写包含 `/v1` 的基础地址及应用 API Key。发布 Workflow 应用，并定义三个文本输入：

- `prompt`：用户问题与可选 Skill 指令。
- `context`：授权业务快照的 JSON 字符串。
- `locale`：`zh-CN` 或 `en-US`。

后端调用 `/workflows/run`，以 `streaming` 模式处理节点进度、`text_chunk`、`workflow_finished`。未输出文本块的流程会展示最终 `outputs`；失败或需要人工交互的流程不会标记成功。目前支持无需交互的 Workflow，未实现 Dify 暂停后恢复或远端任务停止 API。停止生成会中断 AutoOps 的连接和等待；远端服务是否停止执行由其自身决定。

协议参考 [Dify Workflow 服务端入口](https://github.com/langgenius/dify/blob/main/api/controllers/service_api/app/workflow.py) 与 [流事件定义](https://github.com/langgenius/dify/blob/main/api/core/app/entities/task_entities.py)。

### Webhook

填写完整 URL。请求为 POST JSON，可选密钥放在 `Authorization: Bearer ...`：

```json
{
  "prompt": "检查运行风险",
  "context": "{\"generatedAt\":\"...\",\"cmdb\":{...}}",
  "locale": "zh-CN",
  "user": "autoops-17"
}
```

支持 JSON 返回 `{"output":"诊断结果"}`，或 `Content-Type: text/event-stream`：

```text
data: {"type":"delta","text":"第一段内容"}

data: {"type":"delta","text":"第二段内容"}

data: {"type":"done"}

```

失败事件为 `{"type":"error"}`。JSON Webhook 在响应结束后展示结果；SSE Webhook 可逐段展示。空输出、响应超限、断流或缺失终止事件均不算完成。

## 业务证据与权限

诊断 Agent 的执行流程是 **验证账号/配置 → 收集授权证据 → 应用 Skill → 逐步调用模型或外部工作流 → 保存运行记录**。当前为只读业务分析，不运行 shell、不发起资源修改、不执行 SQL 写入，也不会因模型建议自动执行命令。

| 模块 | 提供给模型的证据 |
| --- | --- |
| CMDB | 授权主机、数据库、物理机、网络设备的数量和状态分布 |
| Kubernetes | 账号可访问集群的数量和保存状态 |
| 监控 | 授权主机 Agent 心跳汇总、平台端点/证书检查结果、告警和故障统计 |
| 任务 | 作业、Ansible 的执行状态与时间趋势 |
| 服务管理 | 应用状态、发布执行统计 |
| 配置中心 | 管理员可见的凭据和同步配置数量，不提供凭据内容 |
| 系统管理 | 管理员可见的用户、角色、菜单数量，不提供账号个人信息 |
| 运维工具 | 授权主机上的服务部署状态 |

主机与集群沿用既有 CMDB/Kubernetes 权限校验；应用、任务、端点、证书和告警汇总与现有仪表盘采用相同平台统计范围。配置中心和系统统计对非管理员返回不可访问。未选择的模块不发送给模型。

证据来自数据库中的业务记录，不等同于实时探测。当前不拉取实时日志、Pod 事件或 Prometheus 时序曲线；模型必须说明这些证据缺口，不能声称进行了实时验证。空数据与读取失败保留区别。自由文本告警标题、业务组名称、执行日志、环境变量、密码、SSH 密钥和 kubeconfig 不进入模型上下文；用户主动输入的问题仍会发送至所选服务。

服务端限制每账号同时 1 个诊断、每进程最多 8 个诊断，超时 10–600 秒，模型累计输出不超过 1 MiB，供应商响应不超过 4 MiB。用户断开页面或停止生成会取消请求；服务重启遗留的超时运行在历史中显示“已中断”。多副本部署的并发限制按实例生效。诊断历史目前不自动清理，可按组织保留策略维护 `aiops_run`。

## 密钥与部署

模型和外部工作流密钥使用 AES-256-GCM 加密，API 响应只返回 `hasKey`。编辑时密钥留空保留原值，勾选清除才删除；后端不把供应商原始错误正文返回浏览器。

- `AIOPS_ENCRYPTION_KEY`：可选，Base64 编码的 32 字节随机密钥。可用 `openssl rand -base64 32` 生成后通过 Secret/环境配置注入。多副本必须使用同一密钥。
- `AIOPS_KEY_FILE`：未设置环境密钥时，自动创建 0600 权限密钥文件，默认工作目录下 `data/aiops.key`。
- 密钥必须和数据库一起备份。直接更换密钥会使已保存的凭据无法解密，应使用原密钥启动后重新录入或实施迁移。
- Docker Compose 已增加独立 `aiops-state:/app/data` 卷。
- Kubernetes 已增加 `aiops-state-pvc.yaml` 并挂载 `/app/data`。先创建 PVC；集群没有默认 StorageClass 时，请在该 PVC 中指定可用的 `storageClassName`。
- 密钥卷与公开访问的上传目录分离，不能复用上传卷。
- Docker/Kubernetes Nginx API 代理已关闭 buffering/cache，后端也返回 `X-Accel-Buffering: no`。上层 Ingress/网关同样需要允许 SSE 与长请求。

模型/工作流地址只能由管理员配置。支持内网和回环地址以接入本地模型；拒绝 URL 内嵌账号、查询参数、非 HTTP(S)、链路本地/元数据地址及重定向，DNS 解析在实际连接时验证。

## API

所有接口位于 `/api/v1/aiops`，沿用 Bearer JWT：

| 方法 / 路径 | 用途 |
| --- | --- |
| GET `/catalog` | 当前账号可见配置、模块及管理权限 |
| POST `/configs` | 新建模型 / Skill / 工作流（管理员） |
| PUT `/configs/:id` | 编辑配置（管理员） |
| DELETE `/configs/:id` | 删除配置（管理员）；被工作流引用的 Skill 不能直接删除 |
| POST `/models/:id/test` | 测试已启用模型的真实流式请求（管理员） |
| POST `/diagnose` | 发起诊断；响应 SSE |
| GET `/runs?page=1` | 当前用户的诊断历史，每页 20 条 |
| GET `/runs/:id` | 当前用户的运行详情 |

诊断请求字段：`modelId, skillId, workflowId, prompt, modules, days, locale`。`days` 取 7/30/90；直接诊断和内部工作流必须选择模型，外部工作流无需模型。SSE 事件类型：`start, step, evidence, delta, heartbeat, done, error`。验证失败在开始 SSE 前返回标准 JSON 错误。

## 国际化维护

- `web/src/locales/index.ts`：Vue I18n Composition 模式、语言持久化、`tr` / `$tr`。
- `web/src/locales/en-US.json`：以原始中文为键的英文目录，中文从键生成。消息函数保留 JSON、Go Template、`@` 和 `|` 原文，避免被消息编译器解释。
- 默认中文；登录页与所有导航布局提供语言切换。菜单、面包屑、页签、搜索、页面标题、Element Plus 组件与 AI 输出语言同步。
- 模板使用 `{{ $tr('中文文案') }}` 和 `:label="$tr('中文文案')"`；脚本消息使用 `tr('中文文案')`。选项 `value`、API 枚举、资源名、用户输入、终端输出和日志内容保持原样。
- 后端既有自由文本错误消息保持原文；新增 AI 接口的双语错误按当前语言显示。带业务变量的旧模块消息需使用明确的插值键继续维护，不能翻译整段业务返回数据。
- 执行 `node scripts/i18n-audit.cjs` 检查未迁移静态模板文案，`--json` 输出位置，`--strict` 用于回归检查。语言选项“简体中文”有意保留本地名称。
