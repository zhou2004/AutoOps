# 数据库备份恢复使用指南

数据库管理 → 备份恢复。右上角默认 MySQL，需要操作 Redis 或 PostgreSQL 时先切换类型；从集群行操作进入时自动带入该集群及类型。

## 第一次备份

1. 在“选择操作集群”中选择目标，点击“立即备份”。按钮只在具备备份权限、集群能力满足时开放。
2. MySQL / PostgreSQL 首次可选择“逻辑全量”，Redis 选择“RDB 快照”。物理、增量和日志归档需要额外工具、基线及归档配置，预检会检查这些条件。
3. 选择保存位置。留空使用数据库节点本地暂存；如需独立副本，先按下一节登记仓库。
4. 点击“预检”，查看阻断条件；通过后点击“确认执行”，在最终弹窗核对目标后确认。
5. 任务抽屉显示步骤和日志。完成后进入“恢复演练”，检查文件和保存位置，执行行操作“恢复验证”；验证成功的记录自动进入“备份集”。失败任务只在基础管理 → 数据日志 → 数据库操作审计查看，不混入备份集。

“完整”只说明备份文件完成。是否具有独立副本、是否验证过恢复分别展示，不会因备份完成就自动显示恢复已验证。

## 保存到独立仓库

管理员点击“登记备份仓库”。仓库按业务分组共享，不按数据库引擎隔离。

| 类型 | 需要填写 | 登记后的操作 |
| --- | --- | --- |
| 受管目录 | 业务分组、CMDB 仓库主机、受管目录 | 在仓库列表执行“连接检查” |
| S3 兼容存储 | 业务分组、传输主机、Endpoint、Bucket、Region、配置中心凭据 | 在仓库列表执行“连接检查” |

只有同业务分组且检查正常的仓库可供备份使用。选择受管目录时，要选择数据库节点以外的主机才能形成独立副本。仓库上传及校验完成后才显示“独立仓库已核验”；本地暂存不能替代这个结果。

## 设置自动备份

点击“创建备份策略”，选择集群、方式、保存位置、周期和保留天数。

- 每天 02:00：`0 2 * * *`。
- 每周日 02:00：`0 2 * * 0`。
- 自定义：按“分 时 日 月 周”填写五段 Cron。

调度使用数据库 Worker 所在时区；页面的下次执行时间使用浏览器本地时区显示。保存策略不会立即执行，手动备份使用“立即备份”。策略列表可暂停和恢复调度。保留天数记录预期保存周期；手动清理不受此时间限制，不会据此自动删除文件。

## 从备份恢复与演练

1. 选择状态“完整”的备份集，打开详情核对集群、备份方式、依赖基线、文件位置及恢复范围。
2. 在该行“操作”选择“隔离恢复”或“恢复验证”。当前两者均执行真实恢复和校验。
3. 选择有部署权限的 CMDB 主机，填写空闲的独立端口。不能复用已有数据库实例的端口。Redis Cluster 按分片顺序使用起始端口及后续端口，目标需预留足够资源。
4. 如果出现目标时间选择器，只能选择显示的归档范围内时间。逻辑备份和 RDB 不支持时间点恢复；MySQL binlog 归档必须填写目标时间，精确到秒，目标秒及之后的事件不包含在恢复结果中。
5. 预检通过并确认后，系统取回文件并检查校验值，在新目录恢复数据、启动隔离实例并验证，随后停止隔离实例。
6. 返回备份详情刷新，查看“恢复报告”：目标主机、端口、保留目录、时间点及数据核验结果。失败时查看任务步骤与日志。

**完成后的结果是保留的恢复目录和报告，隔离实例处于停止状态。不会自动覆盖现有业务数据库、加入原集群或切换访问入口。** 若要正式启用恢复数据，需要另行安排实例接管和业务切换。

Redis Cluster 逐分片恢复，不代表跨分片统一事务快照。恢复验证时间对应具体备份与演练，不代表所有未来时间点均可恢复。

## 常见状态与下一步

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| 本地暂存 | 文件仍在数据库节点 | 需要独立副本时登记仓库并在新备份中选择 |
| 未完成 / 失败 | 文件生成、上传或校验未完成，不在备份集中显示 | 基础管理 → 数据日志 → 数据库操作审计查看任务日志 |
| 等待恢复演练 | 完整文件尚无实际恢复报告，只在恢复演练中显示 | 操作 → 恢复验证，成功后进入备份集 |
| 没有完整归档窗口 | 备份缺少连续日志或窗口无交集 | 恢复备份内容；需要时间点恢复时先配置归档并创建对应备份 |
| 结果待核验 | 任务执行结果尚不能确认，互斥锁保留 | 集群操作 → 核验中断任务；先核对实际状态，不重复提交原动作 |
| 清理被阻断 | 文件清单缺失、校验不一致、权限不足或集群任务冲突 | 查看具体预检/执行错误，处理文件和权限；不再检查过期时间或父子引用 |

参数设置现从“集群管理 → 操作 → 参数配置详情”查看和修改，不再单列为数据库管理子菜单。

## 生产恢复场景与交付边界

| 场景 | 使用入口 | 生产后续动作 |
| --- | --- | --- |
| 日常抽检、升级前确认备份可用 | 恢复演练 → 操作 → 恢复验证 | 检查系统报告，再由业务抽查关键数据、事务关系和应用读写 |
| 误删表、错误更新、错误发布 | 备份集 → 操作 → 隔离恢复 | 恢复到错误发生前，导出需要的表/记录，审核新旧数据冲突后回灌 |
| 数据目录损坏、服务器丢失 | 备份集 → 操作 → 隔离恢复 | 从仓库恢复到新主机，校验后接管新实例、重建复制、独立切换业务入口 |
| 单节点故障但副本健康 | 集群管理 → 原生高可用操作 | 按高可用方案切换；备份恢复不是每次节点故障的第一步 |

误操作会通过复制传播，副本不能替代备份。不要为找回几行数据直接把整个生产库回退，覆盖故障后正常写入的数据。

生产执行顺序：

1. 记录故障时间（含时区）、影响表及业务，保留原库、日志与证据。确定能接受的数据缺口和恢复时间；没有归档时只能恢复到快照内容。
2. 核验备份 SHA-256、归档窗口及恢复目标磁盘空间；使用独立 CMDB 主机、目录和空闲端口，隔离实例不接生产入口。
3. 在本页面执行隔离恢复。任务取回文件、实际启动和校验后停止实例，报告记录目录、端口、时间点。系统校验不代替业务语义检查。
4. 按报告在隔离环境人工安排后续数据检查/导出。根据引擎和备份方式确认服务器版本、运行用户及启动配置，不把停止的目录直接覆盖到现有实例。
5. **局部数据找回**：由业务核对行数、主键、约束及后续正常写入，在受控窗口回灌所需数据。**整库恢复**：核对账号权限、应用配置与性能，安排停写或增量补齐，创建独立切换任务接管业务入口。
6. 从业务客户端验证读写，保留旧环境及恢复报告，按实际数据差异报告 RPO；RTO 包括业务重新可用的耗时。

MySQL 逻辑备份只含业务库，不含系统账号；PostgreSQL 逻辑恢复的所有权处理见备份详情，需重新核对角色与权限；Redis Cluster 逐分片快照不是跨分片一致事务快照。当前页面不自动执行生产回灌、复制接管或入口切换。

## 手动清理与仓库删除

- 选择操作集群会同时筛选备份集、恢复演练和策略；清除集群选择可查看当前引擎的全部授权集群。分页总数在筛选之后计算。
- 备份集仅显示 `complete` 且存在实际恢复验证时间的记录，不展示 ID 列。未验证完整备份在恢复演练等待验证，失败任务留在操作审计。
- “清理备份”允许清理未过期备份、最近备份及带历史父子引用的备份，确认弹窗说明删除本地文件与仓库副本。内部动作名 `expire-backup` 和清理终态 `expired` 保留接口兼容。
- 当前 MySQL 增量包携带基线及全部增量；PostgreSQL 物理包携带 pgBackRest 仓库快照；每个归档包独立保存所需恢复数据。父备份 ID 用于追溯来源，删除父包不删除其他包。清理仍校验归属、文件清单、路径和散列，仅删除本次指定备份；不能删除业务数据或任意目录。
- 仓库支持按名称与位置（目录、Endpoint、Bucket）搜索。管理员删除的是平台登记，桶、文件和配置中心凭据保留。仍有完整备份、备份策略或活动任务引用时不删除登记，避免无法再读取已有副本。
- 清理后对应记录从备份集消失，历史任务与报告保留。手动删除最后一份备份后，将没有可用于恢复的备份；确认前按实际业务需求选择。

S3 联调环境与 MinIO 安装教程见 [MinIO 备份仓库](database-minio-guide.md)。

## 恢复任务排队与集群状态未知（2026-11-03）

任务排队表示尚未被后台执行器领取，不代表恢复已经开始。如果启动时间与心跳均为空，先检查 Worker 是否运行，避免重复提交。之前排队锁阻止状态采集，超过 90 秒后源集群显示未知；现已修复，排队与隔离恢复期间继续采集源集群，不通过清除变更锁来恢复显示。

开发模式 `go run main.go -c config.yaml` 在 `server.model: debug` 下默认启动内置数据库 Worker；生产 Compose/Kubernetes 使用独立 Worker，API 设置 `DATABASE_WORKER_MODE=external`。也可用 `--database-worker=external` 明确分进程运行。`auto` 在非 debug 模式不会启动内置 Worker。

排队恢复后的原任务仍要重新检查授权、拓扑版本、端口与备份文件。若已经发生拓扑变化，任务会明确失败并要求重新预检，不会越过校验强行执行。执行过但结果待核验的任务继续按正式核验流程处理，不自动重放。

本次现场核验：原恢复任务 `#249` 于 2026-11-03 23:51:08 被开发 Worker 领取，约 23:52:08 完成。备份 `#36` 在 `.53:14307` 隔离恢复及数据校验通过，恢复实例停止、文件和报告保留；任务锁正常释放。原 MySQL `.51` 主库、`.52/.53` 副本以及复制和业务入口正常，状态未知来自旧采集阻塞，不是本次恢复删除了节点或数据。后端 `go test ./...`、前端构建及操作确认回归通过。

## 备份名称与仓库详情（2026-11-04）

“立即备份”的参数中可填写 **备份名称**，例如“发布前全量备份”“月底结账备份”。支持中文和空格，最多 100 个字符；留空自动生成集群、方式及时间组成的名称。名称保存在任务和备份记录中，不改变文件目录或 S3 对象键。历史未命名记录继续保留，页面以集群、方式和时间识别。

备份集、恢复演练、备份详情和恢复选择器都会展示名称。列表的“集群或备份名称”可搜索这两类名称，业务分组、引擎、集群范围和分页同时生效。

在“备份仓库 → 操作 → 详情”查看类型、业务分组、执行主机、目录或 Endpoint/Bucket/Region、配置中心凭据备注、最近连接检查、受管备份占用、关联策略及最近完整备份。详情不会返回 Access Key/Secret；占用根据平台已核验且尚未清理的清单统计，按当前授权范围展示，不代表整个桶的实时总容量。管理员可从详情执行连接检查以更新检查记录。

数据库运维任务、原生事件、配置变更及日志保存周期统一在 **基础管理 → 数据日志 → 数据库操作审计**。原 SQL 操作日志仍在数据日志的独立标签中，保留原有访问限制；审计删除和保存周期仅管理员可操作。旧审计地址及集群行操作跳转继续携带集群与引擎条件。

本轮验证：命名备份任务 `#250` 成功生成备份 `#56`，中文与空格名称经过确认弹窗、任务队列和实际备份后保持一致；恢复演练可按名称搜索。浏览器核验仓库配置/检查/统计详情、四个本地图标及文字对齐、旧审计跳转和 SQL 日志标签均通过；取消确认未提交任务。
